## 实施顺序

1. **窗口与需求队列（已实现独立核心）**：插件内部纯 C# 核心，默认 Ahead 2，Next／Ahead／本季剩余三策略；依据显式同季集序；会话窗口替换、去重、公平排序。无文件 I/O 或 Jellyfin 回调依赖。
2. **缓存存储与复制（已实现独立核心）**：专用受管根目录、持久索引、单任务限速复制、临时文件与预留预算、完整校验和原子公布。拒绝接管不明非空目录；重启仅恢复验证过的受管项。见 [存储实现与边界](SINGLE_PLUGIN_STORAGE.md)。
3. **容量与播放占用**：容量硬约束、磁盘安全余量、只清理受管文件、LRU 和播放占用保护。必须先解决解析到文件打开的保护间隙，再启用自动淘汰，不能把仅播放开始后的标记当成充分保护。
4. **Jellyfin 接入**：后台处理播放事件和同季查询，把缓存索引接到已验证媒体源包装；UI 提供启用、暂停、策略、容量、速率与队列状态。回调只记录有界快照，拒绝迟到事件；实际复制与元数据查询不阻塞回调。
5. **闭环与发布**：本机先验 E01→E02/E03、完成后新请求命中、跳集、容量不足、占用、失败和重启，再交付新测试包进行真实容器验证。当前不自动修改 NAS 或替换已安装插件。

核心作为插件进程内库，不要求单独部署 Worker；此前 Python／FUSE 原型保留，尚未被本批代码替换。目标文档推荐架构保留原文，待新闭环有证据后再登记整体架构替代决定。

## 当前实现边界

`plugin/JellyCache.Core/PrefetchPlan.cs` 接收宿主适配器构造的单文件 Episode 快照。拒绝特殊季、合并集、重复集序／身份／路径、当前集不匹配及无效配置；其他季不进入窗口。缺集按已知后续集排序，不推测文件名。

`SessionDemand` 最多 128 个有需求会话；停止清除该会话需求，其他会话需求保留；无效更新清除旧需求。近集优先，同级会话轮转；UI 查看不推进轮转。已完成／在途 ID 由未来存储执行器提供并排除。跨会话身份或来源冲突拒绝调度。

规划器只产生需求快照，没有事件序号或超时处理；新增独立存储层已提供复制、在途预留、索引及读取租约，两层尚未通过宿主执行器连接。未来宿主必须先序列化事件并拒绝迟到事件，停止／超时调用清理；启动复制前重新核对需求及来源身份。不能据此声称已实现端到端预取。

检查：`scripts/check-prefetch-core.ps1` 检查独立核心；`scripts/check-single-plugin.ps1` 检查固定官方源码、手动模式回归与实际宿主事件／季集方法；`node scripts/check-prefetch-ui.mjs` 检查页面字段转换及兼容旧配置。0.3已引用核心库并由宿主执行器连接，选中缓存保守保留至重启，完整播放生命周期释放尚未实现；不把合成夹具通过记为NAS自动预取验收通过。
