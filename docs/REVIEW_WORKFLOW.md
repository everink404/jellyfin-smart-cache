# 项目协作约定

生效日期：2026-10-06。适用目录：`jelly cache`。依据：用户本次要求采用引用对话整理的最小流程，并整理当前项目文件夹。

## 最小配置与一个批次

本项目保留当前用户对话为唯一决策入口，由同一对话兼任必要规划、执行和自检。默认不拆分对话；只有复杂方案或高影响变更确需额外判断时才考虑独立规划、评审。多线改动影响共同接口、规则、数据或体验时，才增加受影响批次的对齐检查点。

1. 明确目标、授权范围、限制、依赖、验收条件及已有暂停。
2. 做必要规划；小任务直接说明做法和检查，复杂任务先形成可评审方案。
3. 在授权内实施；常规技术选择和范围内返修自主完成。
4. 运行与影响相称的检查，记录证据、失败和未验证项，完成范围内返修。
5. 按批次提交成果、实际变更、检查结果、限制、待决定项和下一步。
6. 核对退出条件和下一步授权；用户实际验收结果到达后才登记验收结论。

## 授权与状态

在 [当前状态](STATUS.md) 集中记录任务和必要决定，避免多份“最新状态”。工作进度、规划、实现、自动检查、独立评审、用户验收、设备或部署验证、授权分别记述。

方案通过不自动获得实施授权，实现完成不代表检查或用户验收通过，自检不记为独立评审。本次流程启用不批准其他功能，不恢复暂停。暂停和恢复须记录直接用户指示的来源、对象、范围及允许继续的工作；沉默、超时或评审通过不替代恢复指示。

历史状态未知时记录“未核实”，不编造授权、不清空旧决定。取得历史记录后保留原件与来源；存在冲突时核对范围和替代关系，只暂停受影响动作。真实产品取舍、新增范围、授权边界及约定阶段放行集中交用户决定。

跨对话发送消息须有直接用户授权及限定链路；引用或读取对话不构成发送授权。需要交接时按批次汇总，同一报告版本不重复发送，回执不触发反复回复。

## 文件夹整理

先盘点，再建立入口、完成用途明确的可逆归类、归档已证实过期资料，并更新受影响引用。沿用已有目录习惯；只在有内容时建立新目录。

不删除不明文件，不因文件名含“旧”或“临时”就判定过期。历史归档应注明原路径、归档理由和替代资料，保留有效决定、授权、暂停和验收记录。

涉及源码、运行数据库、依赖环境、构建、部署或挂载路径的调整，先检查消费者和依赖；依赖不明时保留原位并记录缺口。只有文档变化时检查内容和链接即可；运行受影响时执行对应验证。

## 批次报告最小字段

项目与批次、目标与批准范围、成果版本或文件、本次差异、各项状态、检查证据、缺口与限制、待决定事项、下一责任方与动作、授权来源及暂停影响。必要用户决定另记日期、内容、允许动作、限制、来源和替代关系。
