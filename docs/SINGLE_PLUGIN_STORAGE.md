# 单插件缓存存储核心

日期：2026-10-13。实现为 `plugin/JellyCache.Core/CacheStore.cs`，检查为 `plugin/CoreChecks/StorageChecks.cs`。0.3已接入后台执行器和媒体源包装；用户此前安装的0.2不包含它。新模式的真实容器验收见PREFETCH_TEST与STATUS。

## 已实现能力

- 专用目录只初始化空目录；独占锁限制单实例。重开时检查所有权格式、索引和文件集合，未知文件与破损索引保留并拒绝打开。拒绝符号链接／reparse point。
- 同时只复制一个文件，重复请求等待后复查。默认 8 MiB/s、256 KiB 缓冲，按累计字节限制平均速率，不是瞬时硬上限。
- 完整文件大小在开始前预留；完成文件与在途预留共同受容量上限约束。只淘汰未占用的受管文件；无法腾出空间就停止新增复制。少量索引等元数据不计媒体预算。
- 复制前及每次写入前检查缓存目录所在文件系统余量。按 [.NET 10 Unix 路径处理](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.IO.FileSystem.DriveInfo/src/System/IO/DriveInfo.UnixOrDefault.cs) 与 [空间查询实现](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.IO.FileSystem.DriveInfo/src/System/IO/DriveInfo.Unix.cs) 使用缓存目录路径，避免误查容器根盘。这是源码核对，尚无 Linux 实测。
- 复制时计算 SHA-256，刷盘后从本地重读校验，复查源长度／时间，成功后才原子改名并公布。部分文件不能取得读取租约。
- 创建文件前先保存未完成记录；取消／异常清理记录明确拥有的文件。重开时清理未提交 `.part`／`.media`，完整项全量本地校验；未知文件不会被清理。
- 冷启动源暂时不可用时保留有效本地缓存，但仍拒绝命中；源恢复且版本匹配可复用。损坏的受管缓存删除，降低容量后按 LRU 收紧。
- 文件被选择时更新 LRU，租约存续期间不允许内部淘汰。删除先持久化意图，删除文件后才移除索引；源文件不作为删除目标。

## 接入契约

`CopyAsync` 返回 Published／AlreadyPresent／CapacityBlocked。I/O 与取消异常由未来执行器记录、退避或回源；本层不无限重试。

`TryAcquire` 返回 `CacheLease`（路径与随机读取流）或 null。同一锁覆盖有效性检查、打开和占用登记，内部淘汰不能插入这段间隙。宿主必须从选择缓存开始持有租约，覆盖下游打开、实际读取及 ffmpeg 全部生命周期；只取得路径后立即释放是不安全的。停止预取需求不等于播放租约可以解除。

存在活动复制或租约时拒绝 Dispose。调用者需先停止复制并释放租约。0.3宿主从选中缓存开始保守持有租约至服务关闭，关闭时先等待复制结束再解除占用；没有实现播放结束即释放。不能把此保守方案宣称为完整播放生命周期关联已完成。

## 验证和限制

`scripts/check-prefetch-core.ps1` 在 `.tools/cache-store-checks/<随机标识>/` 中使用真实小文件，保留夹具便于复核。覆盖完整复制／去重、随机读、租约、容量、LRU、源变化、余量不足和途中耗尽、取消、限速、在途不可命中、并发请求、重开与损坏检查、未提交状态恢复和未知文件保留。

恢复测试通过构造持久化中断状态完成；未执行真实强杀、断电或磁盘故障注入。索引与文件刷盘后分别原子改名，没有目录 fsync，不承诺任意断电持久性。

当前仅 Windows / .NET 10 本机检查；NAS、Linux bind mount、ffmpeg 租约和真正的 E01→E02 自动预取仍待接入验证。后台事件、实际调度、暂停／退避、管理 UI 尚未实现。

目录须专用且由组件独占管理。链接检查不构成对抗外部进程并发替换目录的原子边界；外部删除、硬链接及保持大小／时间戳的静默修改未全面防护。运行时快速检查使用来源和缓存长度／时间，冷启动才全量重算本地摘要。原来源完全失联时拒绝命中，不承诺离线播放。

旧版本仍被租约占用时阻止替换；来源变更会拒绝新命中。复制限速不控制底层挂载预读或阻塞 I/O。其他进程也可能突然消耗磁盘空间，实际写入失败仍需未来执行器处理。
