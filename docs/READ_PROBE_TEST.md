## 构建与安装

在线安装使用原仓库地址 `https://everink404.github.io/jellyfin-smart-cache/manifest.json`，刷新插件目录后查找 **JellyCache single-plugin read test** 0.2.0.0。它是新插件条目，不是旧桥接版的更新。发布状态与在线校验证据见 STATUS B-20261011-05。

该版已通过原 Pages 入口发布；[直接下载 ZIP](https://everink404.github.io/jellyfin-smart-cache/packages/v0.2.0-read-test.2/JellyCache.ReadProbe_0.2.0.0.zip)。在线包 SHA-256：`d62a1c0be893b714cf6f636cee80af2081a58efb6f6cd90746d4fab3b44809e3`。

执行 `powershell -File scripts/build-read-probe.ps1` 编译并运行源代码／接口回归检查；首次取得固定上游源码见 `scripts/check-single-plugin.ps1 -FetchSource`。随后执行 `powershell -File scripts/package-read-probe.ps1` 产生本地 ZIP、MD5 清单和 SHA-256 文件。脚本不上传；清单中的 URL 为拟发布位置，只有实际上传并核验后才可使用。

本地测试包：`.tools/distribution/v0.2.0-read-test.2/JellyCache.ReadProbe_0.2.0.0.zip`。ZIP 根目录仅 DLL 和 deps.json，网页资源已嵌入 DLL；不包含框架、源码、用户配置或媒体。适用于 Linux 容器，程序集没有 Windows 专属读文件实现；真实 Linux 加载仍须验证。

独立测试实例可将 ZIP 解压到 Jellyfin 配置目录的 `plugins/JellyCache.ReadProbe_0.2.0.0/`，再重启。用户常见容器配置根为 `/config`，但必须先核对实际配置挂载，不能按此猜测修改生产目录。也可在后续经验证的插件仓库条目中安装；当前包是否已发布以 STATUS 为准。

重启后应出现插件配置页和日志 `JellyCache read test loaded; routing registration: True`。若状态为 `unsupported-registration`，插件保留原服务，不进行缓存切换。仅接受固定 12.1.0.0 以及预期的内置 singleton 服务注册，避免替换其他插件已修改的媒体源管理器。

## 准备一集测试副本

1. 在测试媒体库选一集普通单文件 Episode，避免多版本、特别篇、合并集或符号链接来源。先记录未启用插件时的起播、续播、拖动和实际播放模式。
2. 管理员自行把该视频完整复制到 NAS 本地目录，确保该目录在 Jellyfin 容器内可见。可以复用现有本地配置挂载中的专用测试子目录；它必须确实位于本地磁盘且有足够空间。插件不会替你建立挂载、复制文件或控制这部分空间。
3. 配置页填写原剧集的容器内完整路径，例如 `/video/测试剧/Season 01/E01.mkv`，以及本地副本路径，例如 `/config/jellycache-test/E01.mkv`。两个路径必须不同，不能填 NAS 宿主路径或相对路径。
4. 勾选启用，点击“保存并重新验证”。后台完整读取两份文件并计算 SHA-256；大文件和慢来源会花时间并占用带宽，先用较小测试文件，避免与正式播放争用。
5. 点击“刷新状态”，等待“校验通过，可以开始新的播放”。验证未完成、文件不同、文件缺失或配置不支持时仍使用原来源，不等待下载。

只有现有 Episode 的 Path 和选中来源精确匹配配置、来源列表唯一且为 File 协议时才切换。静态媒体库 DTO、数据库路径、条目和媒体源 ID 都保持原样。外置字幕仍保留原描述中的路径，不视为已缓存字幕。

## 真实播放测试顺序

| 场景 | 操作与通过证据 |
|---|---|
| 加载 | 重启后配置页可打开，注册日志为 True；无本插件相关启动异常 |
| 未启用 | 从原条目播放，行为与基线一致 |
| 完整命中 | 状态 ready 后重新播放同一集；日志出现 `selection: cache; stage=stream-resolution`，视频可播放 |
| 续播与拖动 | 停止并续播，在多个时间点拖动；原条目和进度记录正确 |
| 直读／重封装／转码 | 覆盖用户实际使用的模式；转码／重封装时确认 ffmpeg 输入为本地副本；直读结合取流日志和宿主 I/O 证据确认 |
| 无效副本 | 停止播放后把配置指向独立的缺失文件或不完整副本，再保存验证；状态拒绝命中，原条目仍能播放 |
| 禁用／卸载 | 停止播放、取消启用再新播放；卸载后重启再播放；仍可从原来源读取 |

状态中的缓存／回源次数只是媒体源解析次数，包括协商和查询，不能当作实际播放命中率。`stage=negotiation` 也不能单独证明已经读到缓存。日志不输出媒体路径；转码日志和 I/O 证据可能包含个人路径，转交前脱敏。

## 当前限制与回退

- 本地检查使用真实官方媒体源管理器和编码状态绑定。2026-10-12 用户容器的 Jellyfin Web 转码测试已确认缓存起播、前后拖动及禁用后原来源播放正常，详见 STATUS U-20261012-01；直放、重封装和无效缓存自动回源尚待验证。
- 本版不管理缓存文件，不删除任何文件。测试期间不要修改、移动或清理副本；尚无完整的播放租约。来源解析后到实际打开文件之间被删除，仍可能失败；不能承诺自动重新打开原来源。
- 初次完整 SHA-256 验证后，播放选择仅检查长度与修改时间。保留长度和时间戳的静默修改不保证检出；需要管理员重新保存触发全量验证。
- 每次来源解析仍调用原媒体源管理器，可能探测原来源，不保证缓存命中后绝无远端访问；原来源完全失联场景未验证。
- 已有转码任务会复用原来源，不要求中途切换。客户端直接访问 SMB／文件路径、路径替换、符号链接和多来源可能绕过或拒绝本次选择。
- 关闭配置立即禁止新的缓存选择；已有转码或打开文件可能仍继续读旧来源。停止播放后再测试回源。移除插件并重启恢复内置服务，媒体库不需改路径。

单插件读取通过真实验证后，才迁入自动预取、容量与占用管理，不把本测试包描述为完整缓存系统。

## 追加验证：缺失缓存与直放

先停止当前播放，保留原文件和缓存文件。本轮无需重装或重启容器。

1. 保持原来源路径不变，勾选启用；将缓存路径暂改为一个确认不存在的容器内路径，例如 `/excache/jellycache-missing-test-20261012.mkv`。
2. 保存并重新验证，刷新状态应显示文件不可用（日志 `file-unavailable`），不能是 `ready`。
3. 从原媒体条目重新播放并拖动。日志应出现 `selection: origin`；若转码，ffmpeg 输入应为原 `/video/...` 路径。确认画面声音正常。这证明启用状态下缺失缓存会拒绝命中并使用来源，不代表播放途中删除缓存也能自动恢复。
4. 停止播放，恢复原缓存路径并重新保存，等待 `ready`。
5. 在播放器取消字幕，画质选择原始／最高，重新播放并查看播放信息。只有显示 Direct Play／直接播放时才计入直放测试；Direct Stream／直接串流属于重封装，Transcoding／转码属于转码。更改这些选项不保证当前媒体与客户端能直放。
6. 记录实际客户端、播放模式、画面声音和拖动结果，提供该时间段取流日志。直放没有 ffmpeg 输入日志，需结合 `stream-resolution` 选中缓存和对应缓存文件 I/O 证据确认真实读取；仅协商日志不够。若仍转码，保留结果并进一步选择兼容媒体／客户端，不改全局转码权限来强制测试。
