日期：2026-10-06。批次：B-20261006-02。状态：方案准备完成，环境信息待补充，技术验证未运行。

依据：[项目目标 v0.1 草案](Jellyfin剧集智能预取缓存系统-项目目标文档.md) 第 5、11、12、13 节。

## 本批要回答的问题

在实际 NAS、网盘接入与 Jellyfin 读取链路上，能否保持同一媒体条目和稳定入口，让新的播放请求读取完整本地缓存，未命中或缓存失效时尝试原远端来源？

先验证这个闭环，再展开播放事件插件、预取队列和资源管理。仅下载成功不足以证明播放链路可用。本方案是验证计划，尚无可行性结论。

| Jellyfin 实际媒体入口 | 用户提供 `/vol02/1000-1-e66ba492/apps/Cloud Sync/video` → `/video`，按文件夹处理 | 实际权限、挂载类型与传播方式待诊断；非 .strm/HTTP 主路线 |
| Jellyfin 环境 | 用户补充版本为 `12.1`，尚未从运行实例核验 | 完整运行版本字符串、Docker 镜像及配置方式 |

首要输入是前两项。取得工具和版本后查对应官方接口资料，再决定验证适配器，不根据工具名称推定能力。后续只收集与验证有关的配置，不收集账号、令牌、网盘凭据或完整私有媒体清单。

### fnOS 初步调查（2026-10-06）

用户已说明“飞牛os自带的接入方式”。[官方权限说明](https://help.fnnas.com/articles/v1/contact/user-role)确认文件管理有远程挂载设备和网盘的能力，并说明挂载的用户可见性限制。[官方飞牛影视说明](https://help.fnnas.com/articles/v1/media/media_install)确认其媒体库可选择远程挂载文件。

以上资料并未验证用户当前的 Jellyfin Docker 读取路径，也不能用飞牛影视的能力替代 Jellyfin 的证据。本次查阅尚未取得原生网盘缓存主动预取、完整性状态和淘汰控制的公开接口依据；这不是“没有接口”的结论。

用户随后确认：百度网盘媒体通过文件夹暴露，将媒体路径映射进容器，Jellyfin 按文件夹处理。这是用户描述的实际读取链路，尚未取得部署配置或读取实测。

当前主调查路线已收窄为文件路径：先验证容器读取挂载文件的能力、读取语义和完整复制能力，然后调查稳定路径下本地缓存与远端来源的选择机制。具体虚拟媒体层实现尚未选定，不将现有 Docker 文件夹映射视为已经支持缓存切换。

拟验证的职责划分：现有 fnOS 挂载保留为只读远端来源；独立本地目录保存受本项目管理的完整缓存；读取层在新的文件打开时选择有效本地副本或原来源。Jellyfin 所见路径保持稳定。此为待验证设计，不覆盖或改写 fnOS 的网盘目录，也不直接操作其内部缓存。

## 接入路线选择

已提供的源路径包含空格，脚本与部署示例必须完整引用。当前 `/video` 直接指向原来源；“文件已下载到独立缓存目录”本身不会让该映射自动选择缓存。

[Docker 官方文档](https://docs.docker.com/engine/storage/bind-mounts/)说明可核查绑定挂载的读写权限与传播设置。后续若引入新挂载层，需要实际验证容器是否可见以及恢复流程，不现在修改生产挂载。[Jellyfin 官方容器文档](https://jellyfin.org/docs/general/installation/container/)作为容器配置调查依据；用户补充 Jellyfin 版本为 `12.1`，按原值记录，待诊断取得完整运行版本字符串再用于插件接口兼容判断。

### 现有链路诊断脚本

已建立 [probe-source.sh](../scripts/probe-source.sh)。在 NAS 上用 Bash 执行，默认只取目录元数据、文件系统类型与挂载传播信息；提供容器名时只读取指定配置字段、运行版本及容器内路径元数据，不输出容器环境变量。

```bash
# 把 jellyfin-container 替换为实际容器名。
bash scripts/probe-source.sh --container jellyfin-container

# 可选：把示例换成一集相对于 video 的文件路径。
bash scripts/probe-source.sh --container jellyfin-container --sample '某剧/Season 01/E01.mkv' --read
```

`--read` 仅在 NAS 端读取头部、中部、末端三个最多 4096 字节块，不落盘，但可能触发接入层更大的内部预读；不在播放高峰运行。每个步骤有超时，失败会停止并返回非零。小范围读取不证明完整下载、源版本一致性或 Jellyfin 播放兼容性。

脚本不修改正式容器、源文件、挂载或缓存。诊断输出可能包含媒体路径，转交前可脱敏。当前开发机为 Windows，未连接 NAS；脚本真实运行结果待收集。

- 若实际入口为挂载文件路径，优先调查现有挂载或文件系统层是否能在同一路径下选择完整缓存与远端来源。先确认读取、占用与异常行为，再选具体实现。
- 若实际入口为 .strm/HTTP，调查稳定代理入口对 Jellyfin 和常用客户端读取的兼容性，包括大小、Range、续播、拖动和转码取流。不能仅证明浏览器可下载就判定可用。
- 若已有接入层缓存可复用，先核实主动预取、缓存身份、空间限制和安全淘汰能力，避免重复存储或竞争。
- 任一路线都先使用独立测试条目与测试缓存目录，不改正式媒体库路径。修改生产入口或部署配置前形成明确变更与恢复步骤，核对授权和依赖。

这些是调查分支，并非已经选定的架构。若验证需要改变目标文档设计基线，记录具体障碍和备选方案，交用户处理实际取舍。

## 验证步骤与证据

1. **记录基线。** 选一组用户可授权读取的测试剧集，记录同一条目的身份、入口、来源身份、客户端和播放模式；记录关闭缓存时的起播、续播与拖动结果。路径脱敏，证据不含凭据。
2. **未命中回源。** 使用空测试缓存，正常播放，不等待后台预取；以入口读取日志或可核实的 I/O 证据确认回源，而非仅观察播放画面。
3. **完整缓存准备。** 在独立测试缓存目录下载测试文件。完成必要一致性检查后再公布为有效缓存；临时或不完整文件不能命中。源身份判断能力和限制单独记录。
4. **新请求本地命中。** 通过同一媒体条目开始新的播放请求，确认视频读取来自本地完整缓存，检查起播、续播、多个位置的拖动和实际使用的直放／转码路径。保留外置字幕等附属资源依赖说明。
5. **失效与异常。** 分别测试缓存不完整、源版本变化和缓存不可用，确认新的请求尝试回源。测试 Worker 停止时入口仍能否回源；单独验证媒体入口自身停止后的恢复或旁路，不能混为同一结果。
6. **整理结论。** 为每个场景保存环境、成果版本、预期、观察、结果、限制和脱敏证据。形成可继续、需返修或待验证结论；未运行场景明确保留。

缓存切换只发生在新的播放请求边界。本批不要求正在播放的远端流切换为本地流，也不承诺本地读错误后的无缝续接。

## 首批退出条件

- 确认一种实际网盘接入链路和稳定媒体入口，适配方式有官方资料与实测依据。
- 同一 Jellyfin 条目下，未命中回源、完整本地命中、不完整／失效缓存回源均有证据。
- 代表性客户端起播、续播、拖动及实际使用播放模式有证据，不能以文件下载替代播放验证。
- Worker 停止与入口自身异常分别记录；明确当前回源能力及恢复限制。
- 不改源文件、不破坏媒体身份和续播记录，不把测试缓存目录之外的数据纳入清理。

本地模拟测试可以验证规则和适配器，实际 NAS 与客户端验收单独记录。在未取得真实环境证据前，不将端到端验收标为通过。
