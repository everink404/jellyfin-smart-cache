终点：在约定NAS、Jellyfin12.1和代表客户端上，交付可安装、可回退的单插件；核心播放路径用完缓存后可安全回收，容量硬约束及播放保护成立，预取／回源／恢复／管理功能完成真实验收，并有实际收益或不足的对照报告。沿用原插件身份、原GitHub仓库与Pages入口，无新增Worker部署。

## M1：下一次实际开发的交付终点

按以下顺序连续执行，范围内实现、返修和检查由本对话完成，不要求用户每增加一组检查就回复“继续”。

1. **接入必要生命周期。** 在官方12.1实际调用链连接请求作用域、转码作业及字幕／附件提取。后台任务启动前取得保护，等待明确结束后归还；请求与后台各自持有引用。同一缓存多客户端、seek重开、旧作业迟到结束均不能误释放。
2. **解决预协商积累。** 仅协商未播放不应无条件永久占用全部候选缓存；验证实际取流重解析与保护交接，不能靠固定TTL猜测安全。无法关联的读取者可以保守保护，但必须说明原因、数量与影响；常用Android TV转码路径不能全部仍保护至重启却宣称释放已完成。
3. **完成实际宿主验证。** 在隔离的完整Jellyfin12.1宿主核对插件加载、服务注册／管线顺序、实际ffmpeg和字幕任务、播放后回收及容量压力下占用保护。本机真实HTTP实验可复用，但不能替代这一步。先确认可用宿主与ffmpeg；Docker不是必须前置条件。没有完整宿主或进程证据时，明确登记缺口，不能写成已接入通过。
4. **形成并分发成品。** 更新版本、构建ZIP、核对依赖与校验；按既有仓库／Pages发布流程核验源码、清单版本、匿名下载与ZIP校验一致。交付时给出准确版本、原仓库地址、升级步骤、无需重复的测试和回退0.3.1步骤。

M1门槛同时包括：缓存实际使用时不被淘汰；常用路径结束后在不重启服务的情况下能够回收；原媒体身份、续播和回源不退化；真实宿主启动及依赖循环检查通过；诊断能解释失败与保守保护；保留旧包和配置兼容。第一包默认与启用方式须在成品说明中明确，不默默改变NAS设置。

**调查必须收敛为结果。** 下一开发批次先核对剩余官方接入点，然后交付实际接入或具体阻塞报告；不再以扩展外围夹具作为独立交付终点。若缺少可靠接口／运行环境，报告必须列出具体调用点、已尝试方法、证据、受影响路径、最小可行修正及对目标的影响。可以提交诊断候选，但这不满足M1完成条件。若必须削减目标或改变架构，先形成具体取舍给用户决定，不自行用有限方案替代原目标。

## M2：目标功能完善与真实验收

2026-10-16实施入口：0.4.0已取得NAS转码／seek／停止后保护归零样本，0.4.1新增安全清理成品与完整隔离宿主检查，见[M2交付](M2_DELIVERY.md)。它是本阶段功能补齐，不代表下表全部真实验收完成；实际进度仍以STATUS为准。

M1实际接入通过后，完善原目标范围并按下面矩阵逐项验收。已取得证据且未受变更影响的项目可以复用；受生命周期改动影响的缓存播放／seek须回归。

| 必须项 | 通过证据 |
|---|---|
| 默认Ahead2与去重 | 同季后续两集、下一集优先，多次进度不重复下载；copy完成与后续真实输入身份对应 |
| 跳集、三策略、季末 | Next／Ahead／本季剩余符合当前配置；跳集替换需求；季末不跨季，含糊／特殊／多版本保持安全路径 |
| 暂停与恢复 | 在途复制取消、未完成项不命中、暂停不影响已完成缓存播放；恢复按当前窗口继续 |
| 容量与安全淘汰 | 已完成、临时及预留受预算约束；无空间时等待并保留原播放；只清理受管且无占用的项，不来回淘汰当前窗口 |
| 播放与任务保护 | 同缓存并发读取、seek和字幕任务期间不删除；真正结束后可回收，无需依赖周期重启 |
| 失败与回源 | 复制失败分类、有限退避；缺失／无效／变化缓存不使用；来源完好时新请求能回源；异常不能阻断原播放 |
| 中断与重启 | 中断复制后清理有记录的临时项，不误当完整缓存；完整缓存恢复；新播放重新建立需求，不恢复过期会话 |
| 代表客户端实际模式 | 当前Android TV与Web等实际使用客户端的转码／重封装／可适用直放，起播、续播、前后seek及字幕有证据；实际不适用的模式解释原因，不能无证据全勾通过 |
| 安全管理与可观察性 | 补齐目标文档中尚缺的“清理未占用受管缓存”能力；配置／队列／失败／保护状态可查；清理不能删除原文件、未知文件和活跃读取项 |

每项记录版本／校验、环境、操作时间、预期、实际结果、日志及必要用户反馈。失败先返修并只重测受影响项目，不能以累计检查数量代替通过结论。

本对话负责代码、打包、分发核验、日志获取分析和状态更新。现有MCP只读通道可取日志与会话，但不能因此宣称已能远程改插件配置、控制播放或重启Docker。到真实操作步骤时，只列出完成该批必需的安装／重启／播放动作，合并请求用户执行；若建立写操作通道，需有明确限定授权和空闲窗口。规划不修改现有只读配置。

## M3：收益与验收基线

交付配对对照报告：同条目、客户端、播放模式及近似网络条件下，缓存启用与禁用至少5组起播观察，无需每次完整看完剧集。记录样本数、测量口径、中位数／范围、缓存是否真实命中、原挂载缓存与顺序效应。不能控制的条件写明。

客户端首帧能可靠取得时才报告真实起播耗时；只有服务端日志时明确是取流／转码准备时间代理，不把它当作首帧。远端流量、CPU／磁盘资源等能取得才报告，不能从插件选择计数推算实际播放命中率或流量节省。没有明显收益或反而变慢也须如实交付，登记目标尚未证实并给出原因及修正建议。

最终材料包括：已验收版本与校验、安装／升级／配置、暂停／清理／恢复、已知限制、源完全离线与外置字幕边界、回退办法、验收矩阵及收益报告。用户画面声音反馈与日志检查分开记。必要功能仍有未通过项时，不宣布可长期使用或项目全部完成。
