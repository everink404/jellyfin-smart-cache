# Jellyfin 剧集智能预取缓存插件/系统

项目目标文档 · PRD + 技术目标  
版本：0.1 草案｜日期：2026-10-06｜状态：目标整理完成，接入方式与技术可行性待确认

## 1. 项目背景

当前 Jellyfin 部署在本地 NAS 的 Docker 环境中，元数据保存在 NAS，视频文件主要存储在远端百度网盘。本地存储容量有限，无法长期保存全部剧集。远端读取导致剧集首次打开、起播及连续观看时容易出现等待和卡顿。

用户可以接受首次观看一部剧时，当前集仍需从远端读取并存在一定等待；希望利用观看当前集的时间，提前将下一集、后续若干集或本季剩余剧集缓存到 NAS，改善连续观看体验。

本项目以已有 Jellyfin 剧集库为基础，不承担媒体资源获取或媒体库重建职责。

## 2. 产品定义与核心目标

**一个理解 Jellyfin 连续观看行为的智能预取缓存系统：当用户播放远端剧集时，后台预测后续观看内容，将其预下载到 NAS 本地缓存池；后续播放优先读取完整、有效的本地缓存，未命中时继续通过原有远端来源播放。**

核心目标：

- 服务番剧、电视剧等具有 Series → Season → Episode 关系的媒体。
- 当前集播放期间，主动预取下一集、后续 N 集或本季剩余剧集。
- 在有限空间内，提高连续播放的缓存命中率，减少后续集起播等待。
- 保持原有选集、续播、播放历史和媒体库体验，避免生成重复条目。
- 后台缓存服从前台播放需求，避免预取加重当前集卡顿。
- 缓存不可用或系统异常时，尽可能保留原有远端播放能力。

目标是改善后续集播放体验，不承诺消除所有卡顿。效果取决于远端速度、文件大小、可用空间、客户端播放方式及本地转码能力。

## 3. 非目标

- 电影、音乐、Live TV 的缓存与预取。
- 全媒体库镜像、永久下载收藏或完整百度网盘同步。
- 改造 Jellyfin 客户端或实现新的播放器。
- 解决所有转码性能、网络连接或网盘服务限制问题。
- v0.1 不实现复杂观看兴趣预测、自动跨季预取、多节点缓存或跨 NAS 调度。

## 4. 核心用户体验

以一季 12 集番剧、默认 Ahead 2 策略为例：

1. 用户正常打开 E01。若缓存未命中，当前集按现有远端链路播放，不等待预取完成。
2. 系统识别当前剧集，立即将 E02、E03 纳入预取窗口，优先下载 E02。
3. 完整下载并通过必要完整性检查后，缓存才成为可用于播放的命中项。
4. 用户播放 E02 时，若已有有效缓存，则通过同一媒体入口读取本地文件；窗口推进至 E03、E04。
5. 用户跳到 E08 时，预取目标调整为 E09、E10，旧窗口任务降级或取消。
6. 缓存未完成、下载失败或空间不足时，用户仍可尝试从原远端来源播放。
7. 管理员可以查看容量、命中情况、下载队列及失败原因，调整策略、暂停预取或清理未占用缓存。

缓存切换以新的播放请求为边界。v0.1 不要求将正在播放的远端流无缝切换为本地流，也不将未完成的文件作为完整缓存使用。

## 5. 推荐架构与职责

推荐采用 **Jellyfin Plugin + 独立 Cache Manager/Worker + 稳定媒体入口** 的分层架构。

```text
Jellyfin 播放事件与剧集关系
              │
              ▼
Jellyfin Plugin：感知播放、确定后续剧集、生成预取意图
              │
              ▼
Cache Manager/Worker：队列、下载、缓存索引、资源控制、淘汰
              │
              ▼
NAS 本地缓存池 ← 现有接入链路 ← 百度网盘

播放读取链路：
Jellyfin → 统一媒体入口/虚拟媒体层
                    ├─ 有效命中 → NAS 本地缓存
                    └─ 未命中   → 原有远端来源
```

| 组件 | 主要职责 |
| --- | --- |
| Jellyfin Plugin | 感知播放开始、进度、结束和选集变化；识别剧集关系；计算预取目标和优先级；提交、更新预取意图；提供必要配置与状态入口 |
| Cache Manager/Worker | 去重排队；远端下载；限速与并发；空间预留；完整性与有效性检查；缓存索引；失败重试；淘汰与异常恢复 |
| 统一媒体入口/虚拟媒体层 | 保持 Jellyfin 所见媒体身份与访问入口稳定；按缓存状态选择本地读取或回源；满足实际播放需要的读取语义 |
| 现有网盘接入层 | 提供可授权读取的远端来源，承接网盘认证及既有挂载或代理能力 |

**优先采用统一媒体入口或虚拟媒体层，避免通过动态修改 Jellyfin 媒体库路径来切换缓存。** 稳定入口有利于保持条目、续播及媒体信息的一致性；具体使用文件系统层、代理层还是已有挂载层，必须根据现有环境验证后确定。

以上是推荐设计，不代表已确认 Jellyfin 插件接口或现有挂载工具能直接实现全部能力。尤其应验证 Direct Play、Direct Stream、转码、随机读取和拖动进度等实际读取路径。

## 6. v0.1 范围

v0.1 应交付一个可验证的端到端闭环：**播放触发 → 预取 → 完整缓存 → 后续集本地读取 → 未命中回源**。

包含：

- 支持已正确识别为 Episode 的番剧、电视剧；按已识别季集顺序寻找同季后续集。
- 支持 Next Episode、Ahead N Episodes、Whole Season 三种策略，默认 Ahead 2。
- 播放开始触发、窗口随选集更新、重复事件与重复任务去重。
- 支持一种经过验证的网盘接入方式；不要求同时适配所有候选工具。
- 独立下载队列、可配置预取限速与并发，初始建议单下载任务并发。
- 缓存容量上限、磁盘安全余量、下载空间预留、LRU 淘汰和播放占用保护。
- 缓存有效性检查、失败重试、失败回源、临时文件和重启恢复处理。
- 最小管理能力：策略、容量、资源限制、队列与错误状态、暂停预取和安全清理。
- 验证缓存命中后的实际播放、续播和拖动进度，不仅验证文件下载成功。

暂缓：基于速度与剩余播放时间的精细预测、复杂多用户公平调度、自动跨季、特殊集排序推断和不完整文件的边下边播缓存。多会话至少应能够去重并避免相互淘汰正在播放的文件。

## 7. 预取策略

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| Next Episode | 预取当前集之后的下一集 | 空间或带宽较紧张 |
| Ahead N Episodes | 始终维护当前集之后 N 集的预取窗口；N 可配置 | 常规连续观看，默认 N = 2 |
| Whole Season | 按播放顺序预取当前集之后的本季剩余剧集 | 连续追剧、空间较充足 |

共同规则：

- 以 Jellyfin 已识别的同季集序为依据，不只根据文件名猜测下一集。
- Whole Season 在 v0.1 指当前集之后的本季剩余集，不补齐已跳过的前序集。
- 默认不跨季；到季末停止扩展窗口。特殊集、缺失集或集序不明确时，不盲目推断。
- 已有效缓存或已在队列中的相同文件不重复下载；历史已看状态不妨碍用户重看时预取当前窗口。
- 三种策略均受容量与播放资源限制约束，整季模式也不保证全部缓存完成。

## 8. 触发逻辑与优先级

### 触发逻辑

- **播放开始或切换剧集：** 确认 Episode 与来源适用后，立即计算窗口，无需等待固定播放百分比。
- **播放进度：** 适度合并事件，检查队列与窗口，必要时补充或调整任务；不因每次进度上报重复创建下载。
- **预取完成：** 继续处理窗口中的后续任务，保持下一集优先。
- **播放停止、结束或会话超时：** 更新播放占用；若未进入下一集，暂停该会话尚未开始的预取任务。已开始任务在资源允许时可完成，任务也可能因资源压力被暂停。
- **容量不足或播放受影响：** 暂停、降速或取消低优先级预取；条件恢复后再继续。

暂停与停止应区分：暂停保留预取窗口，但后台资源仍应受限。事件可用性与停止判定需在目标 Jellyfin 版本验证。

### 优先级

1. 当前播放所需远端读取、磁盘读取及转码资源具有最高保障优先级。
2. 活跃会话的下一集预取。
3. 活跃会话窗口中的其余后续集，距离当前集越近越优先。
4. Whole Season 中较远的剧集，以及会话已结束后保留的在途任务。

相同文件合并为一个任务。多会话之间采用简单轮转或同级公平排队，避免整季任务占满队列。

“下一集必须在当前集结束前下载完成”是期望，不是硬保证。后续可结合文件大小、实际吞吐和剩余观看时间评估是否来得及，但提高优先级不能突破播放优先原则。

## 9. 空间管理与 LRU

- 配置缓存容量上限，并保留 NAS 磁盘安全余量。已完成文件、下载临时文件与任务预留空间都纳入预算。
- 启动任务前检查所需空间；文件大小未知时采取保守限制，避免无限增长。
- 缓存满时，优先清理失效、过期或遗留临时文件，再从可淘汰项中按 LRU 回收。
- LRU 以最近实际播放或读取时间为主要依据；下载完成时间不等同于用户访问时间。
- 正在播放、下载或被活跃读取的文件不得淘汰。下一集和活跃预取窗口可给予较高保留优先级。
- 已观看内容可以作为优先回收候选，但不能删除仍有播放占用的文件。
- 无可安全回收空间时，停止新增预取，并保留远端播放入口；不强制下载整季。
- 删除操作仅作用于本项目管理的缓存与临时文件，不删除网盘原文件、Jellyfin 元数据或其他 NAS 数据。

缓存须绑定明确的源文件身份与版本信息。源文件变化后旧缓存应失效，避免播放错误版本；具体判断依据取决于接入层提供的信息。

## 10. 失败回源与播放优先

| 情况 | 期望行为 |
| --- | --- |
| 缓存未命中或尚未完成 | 本次播放通过原有远端来源，不等待预取 |
| 下载失败、认证失效或远端限流 | 标记原因，有限次数重试并退避；不无限并发或高频重试 |
| 缓存校验失败或源文件已变化 | 不使用该缓存，失效处理后回源并按策略重新预取 |
| 下载挤占当前播放资源 | 降低预取速率或并发，必要时暂停预取 |
| 磁盘空间不足 | 停止新增任务，执行安全淘汰；不能回收时保留远端播放 |
| Plugin 或 Worker 异常 | 预取停止；媒体入口应尽可能继续提供远端读取 |

失败回源只能恢复到原有远端能力，不保证远端本身可用。若播放中的本地文件出现读错误，v0.1 不承诺无缝续接；应报告错误，并在新的播放请求中尝试回源。

优先使用明确的资源预算与配置限速保障播放。仅在现有接入层能够可靠观测或控制带宽时，再增加自动降速逻辑。统一媒体入口本身的异常旁路和恢复方案必须验证，不能仅凭 Worker 独立部署就认为播放不会受到影响。

## 11. 验收目标

在确定的 NAS、Jellyfin 版本、客户端和接入方式上，完成以下验证：

1. 播放 E01 后自动产生 E02、E03 的默认预取窗口，E02 优先；多次进度事件不重复下载。
2. E02 缓存完成后，播放仍使用原有媒体条目与稳定入口，并能确认视频读取来自 NAS 缓存。
3. 切换到 E08 后窗口更新至 E09、E10，旧队列按规则降级或取消。
4. 三种策略行为与配置一致，季末不越界或意外跨季。
5. 未完成或失效缓存不作为完整命中项；未命中、任务失败时能够尝试回源。
6. 达到容量限制时可淘汰未占用缓存，不删除正在播放文件或源文件；临时文件不无限积累。
7. 能暂停预取并恢复播放资源，Worker 重启后任务与缓存状态可恢复，不留下误判为完整的文件。
8. 代表性客户端的起播、续播、拖动进度及实际使用的直放/转码模式通过验证。

记录连续播放缓存命中率、后续集起播耗时、下载吞吐、回源次数和资源占用。用相同条件下启用/停用预取的对照确认收益；具体起播耗时与命中率指标待接入环境和实测基线确定。

## 12. 后续必须确认的技术前提

这些问题决定具体实现方案，当前不作为已确认事实：

| 待确认项 | 需要提供或验证的信息 | 对设计的影响 |
| --- | --- | --- |
| 百度网盘接入链路 | 当前使用 rclone、CloudDrive2、AList、OpenList、WebDAV、百度网盘客户端挂载、其他 FUSE 或组合方式；各工具版本 | 决定下载来源、缓存位置和可用控制接口 |
| Jellyfin 实际媒体入口 | 容器内看到的是文件路径、挂载目录、HTTP 地址还是 .strm；NAS 与容器之间如何映射 | 决定统一入口放在文件系统层还是代理层 |
| 现有接入层的缓存 | 是否已有 VFS/读缓存，容量、预读、限速和淘汰如何配置 | 避免重复缓存、额外空间占用和资源竞争 |
| 远端读取能力 | 是否支持随机读取、HTTP Range、文件大小/版本信息、断点续传及稳定访问；认证是否过期 | 决定完整性判断、续传与播放兼容性 |
| Jellyfin 环境 | 版本、插件事件与媒体关系接口可用性、播放事件是否覆盖实际客户端 | 决定 Plugin 感知与决策能力 |
| NAS 与部署资源 | 系统及 CPU 架构、缓存磁盘、可用容量、Docker 权限、网络与转码负载 | 决定部署方式、容量和资源预算 |
| 观看方式 | 常用客户端、直放或转码、同时观看人数、字幕与多版本剧集使用情况 | 决定播放链路验证及缓存对象选择 |
| 文件身份与附属资源 | 同集多版本如何选定；外置字幕等是否依赖远端；源文件如何识别变化 | 避免预取错误版本，并识别本地命中后仍存在的远端依赖 |
| 配置与运维入口 | Jellyfin 插件配置页是否足够，Worker 状态如何查看及恢复 | 决定最小管理界面与维护方式 |

首要确认项是：**百度网盘目前如何接入 NAS/Jellyfin，以及 Jellyfin 容器实际读取的媒体入口是什么。** 确认后先验证“同一媒体入口下，完整缓存本地命中、未命中回源”的最小方案，再细化接口、任务状态和部署配置。

## 13. 设计基线

后续开发默认遵循：仅针对剧集；Plugin 负责感知与预取决策；Worker 负责大文件与资源管理；稳定媒体入口优先；默认 Ahead 2；仅完整有效缓存参与命中；缓存容量有硬约束；播放占用受保护；缓存失败允许回源；播放优先于预取。

如后续技术验证要求改变上述基线，应同步更新本目标文档并记录原因。本文定义目标与边界，不替代接入可行性验证、接口设计或部署说明。
